# 观察与触发事件

## 定义

观察与触发事件是结构化产品生命周期中的批处理核心：在预设观察日判定敲入、敲出、票息支付与自动赎回，驱动合约状态变更。

## 原理 / 结构要素

### 事件类型

| 事件 | 触发条件 | 后果 |
|------|----------|------|
| `OBSERVE` | 观察日到达 | 记录观察价格，无状态变更 |
| `KNOCK_IN` | S ≤ B_in（Down-and-In） | 状态 → KNOCKED_IN |
| `KNOCK_OUT` | S ≥ B_out（Up-and-Out） | 状态 → KNOCKED_OUT，提前终止 |
| `AUTOCALL` | S ≥ B_out（Autocall 产品） | 提前赎回结算 |
| `COUPON` | 票息观察日 + 未敲入 | 生成票息现金流 |

### 批处理执行顺序（固定）

```
1. 加载当日观察日合约列表
2. 获取观察日收盘价 Spot
3. 判定 KNOCK_OUT（优先）
4. 判定 KNOCK_IN
5. 判定 COUPON / AUTOCALL
6. 写入 Event Log
7. 触发估值重算
```

## 业务规则

1. 观察价格以**收盘价**为准（条款约定）。
2. 敲出优先于敲入（同日触发时的默认规则，以条款为准）。
3. 敲入保护期内跳过 KNOCK_IN 判定。
4. 已 KNOCKED_OUT 或 CLOSED 的合约跳过所有观察。
5. 已 KNOCKED_IN 的合约不再判定 KNOCK_IN，但仍可能 COUPON（依条款）。
6. 观察日无市场数据（停牌）时：沿用前一交易日价格 / 跳过 / 人工介入（依条款）。
7. 同一合约同一观察日事件幂等：重复跑批不产生重复事件。

## 工程实现要点

- Job：`ObservationBatchJob`，Cron 在收盘价发布后触发（如 18:00）。
- 输入：`observationDate`、合约观察日列表、MarketData Spot。
- 幂等键：`contractId + eventType + observationDate`。
- KNOCK_IN/OUT 不生成现金流，仅更新 `Contract.status` + 写 Event Log。
- COUPON 生成现金流，由 CouponHandler 或 PremiumHandler 处理。
- KNOCK_OUT 后链接 SETTLE 流程，生成 PaymentOptionHandler 现金流。
- 失败重试：单合约失败不影响其他合约；失败记录告警队列。

1. 观察日批处理的完整步骤。
2. 为什么敲出优先于敲入判定。
3. 敲入事件为何通常不产生现金流。
4. 停牌日如何处理观察价格。
5. 如何保证批处理幂等性。
6. 观察日与 Fixing 日的区别（亚式 vs 雪球）。
