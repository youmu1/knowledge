# 生命周期事件设计

## 定义

生命周期事件是驱动场外期权合约状态变更、现金流生成与估值重算的原子业务动作；系统设计需保证事件可枚举、幂等、有序、可审计。

## 原理 / 结构要素

### 事件类型枚举

| 事件类型 | 触发方式 | 状态影响 | 产生现金流 |
|----------|----------|----------|------------|
| `BOOK` | 实时 | DRAFT 创建 | 否 |
| `OPEN` | 实时 | → LIVE | 是（Premium, TradeFee） |
| `OBSERVE` | 批处理 | 无 | 否 |
| `KNOCK_IN` | 批处理 | → KNOCKED_IN | 否 |
| `KNOCK_OUT` | 批处理 | → KNOCKED_OUT | 是（结算金） |
| `AUTOCALL` | 批处理 | → CLOSED | 是（结算金） |
| `COUPON` | 批处理 | 无 | 是（票息） |
| `UNWIND` | 实时 | → UNWOUND/CLOSED | 是（结算金, TradeFee） |
| `EXERCISE` | 实时/批处理 | → SETTLED | 是（结算金） |
| `ABANDON` | 批处理 | → CLOSED | 否 |
| `EXTENSION` | 实时 | Terms 版本++ | 是（展期费） |
| `DIVIDEND_ADJ` | 批处理 | Terms 调整 | 可能 |
| `CORP_ACTION` | 批处理 | Terms 调整 | 可能 |
| `EXPIRE` | 批处理 | → EXPIRED | 否 |
| `SETTLE` | 批处理 | → SETTLED → CLOSED | 是（结算金） |
| `MARGIN_CALL` | 批处理 | 无 | 否 |

### Event Payload 结构

```json
{
  "eventId": "uuid",
  "contractId": "C20250101001",
  "eventType": "KNOCK_IN",
  "eventDate": "2025-06-15",
  "termsVersion": 1,
  "payload": {
    "observationPrice": 78.5,
    "barrierPrice": 80.0,
    "triggerReason": "S <= B_in"
  },
  "status": "PROCESSED",
  "createdAt": "2025-06-15T18:05:00Z"
}
```

### 事件 → 现金流映射表

| 生命周期事件 | 典型现金流类型 | Handler |
|-------------|---------------|---------|
| OPEN | 期权费（Premium）、交易费 | PremiumHandler, TradeFeeHandler |
| UNWIND | 平仓结算金、交易费 | PaymentOptionHandler, TradeFeeHandler |
| SETTLE | 到期结算金 | PaymentOptionHandler |
| KNOCK_OUT / AUTOCALL | 提前赎回结算金 | PaymentOptionHandler |
| COUPON | 票息 | CouponHandler / PremiumHandler |
| EXTENSION | 展期费 | ExtensionFeeHandler |
| DIVIDEND | 分红调整 | DividendHandler |
| KNOCK_IN / KNOCK_OUT（仅敲入） | 通常无 | 状态变更 + 估值重算 |

## 业务规则

1. 每个事件必须有唯一 `eventId` 和幂等键 `contractId + eventType + eventDate`。
2. 事件处理顺序：**状态变更 → 现金流 → 估值 → 风控**，任一步失败则整体回滚。
3. 批处理事件仅在 Market Data 就绪后执行。
4. 同一合约同一观察日不可重复 KNOCK_IN / KNOCK_OUT。
5. `CLOSED` 状态合约拒绝所有新事件。
6. 事件 Payload 必须引用 `termsVersion`，保证审计时可还原条款。

## 工程实现要点

### 幂等与重放

- 写入前检查幂等键：`INSERT ... ON CONFLICT DO NOTHING` 或 Redis 分布式锁。
- 重放：按 `eventDate` 排序重放 Event Log，可重建合约状态（Event Sourcing）。

### 并发控制

- 单合约事件串行：同一 `contractId` 加乐观锁（`version` 字段）或分布式锁。
- 批处理按合约分片并行，片内串行。

### 批处理 vs 实时

| 维度 | 实时 | 批处理 |
|------|------|--------|
| 触发 | API / 用户操作 | Cron Job |
| 延迟 | 毫秒级 | 小时级（日终） |
| 典型事件 | OPEN, UNWIND, EXTENSION | OBSERVE, KNOCK_IN, SETTLE |

### 事件总线（可选）

- 事件写入后发布到 MQ，下游（现金流、估值、风控）异步消费。
- 保证 At-Least-Once，消费端幂等。
