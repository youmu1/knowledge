# OS - IO模型

## 定义

IO 模型描述应用发起 IO 请求后，数据准备与数据拷贝阶段的交互方式。

## 原理

1. 常见模型：阻塞 IO、非阻塞 IO、IO 多路复用、信号驱动 IO、异步 IO。
2. 关键区分点：等待数据阶段是否阻塞；数据拷贝阶段由谁完成。

## 应用场景

1. 高并发网关。
2. 长连接服务。
3. 大量短连接 API 服务。

## 高频问题回答

### 异步和非阻塞的区别？

1. 非阻塞：调用立即返回，但需主动轮询结果。
2. 异步：内核完成后主动通知应用（回调/事件）。

### 多路复用/阻塞非阻塞的理解？

1. 多路复用（select/poll/epoll）让单线程监听多个 fd 事件，减少线程数。
2. 阻塞/非阻塞是单次 IO 调用行为；多路复用是事件分发机制。

## Spring Boot 实践案例

1. Servlet 阻塞栈：Tomcat + Spring MVC，线程模型简单。
2. 非阻塞栈：WebFlux + Reactor Netty，适合高并发 IO。
3. 规则：若存在大量外部 IO 且延迟高，优先评估 WebFlux；CPU 密集业务优先线程池隔离。
