# Network - TCP专题

## 定义

TCP 是面向连接、可靠传输、字节流协议。

## 原理

1. 通过序列号、确认应答、重传机制保证可靠性。
2. 通过窗口机制进行流量控制。
3. 通过拥塞控制保护网络稳定。

## 应用场景

1. HTTP/HTTPS。
2. 数据库连接。
3. 需要可靠传输的内部 RPC。

## 高频问题回答

### 拥塞控制

1. 典型阶段：慢启动、拥塞避免、快速重传、快速恢复。
2. 目标是在吞吐与网络稳定性间平衡。

### 与UDP差异

1. TCP：可靠、有序、面向连接，开销更高。
2. UDP：无连接、尽力而为，时延低，适合实时音视频等。

### 滑动窗口

1. 发送窗口决定未确认数据上限。
2. 接收窗口反映接收端可用缓冲能力。

### 粘包

1. TCP 是字节流，不保留消息边界，因此会出现粘包/拆包。
2. 解决方式：固定长度、分隔符、长度字段协议。

## Spring Boot 实践案例

1. 高并发接口应设置合理连接超时、读超时、写超时。
2. 使用连接池（如 HTTP Client）复用 TCP 连接，减少握手成本。
3. 对调用方设置重试上限和退避策略，避免雪崩放大。
4. 长连接服务需配合心跳和空闲连接清理。
