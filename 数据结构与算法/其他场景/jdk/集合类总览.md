# JDK - 集合类总览

## 定义

JDK 集合框架（`java.util`）提供一组标准接口与实现，用于在内存中组织、检索和操作一组对象。核心分为两条继承线：

1. **`Collection`**：元素可重复或唯一，元素本身即值。
   - `List`：有序、可重复。
   - `Set`：不重复（是否有序取决于实现）。
   - `Queue` / `Deque`：按 FIFO 或双端规则出入队。
2. **`Map`**：键值对存储，键唯一，值可重复；不继承 `Collection`。

所有集合类均实现 `Iterable`，支持增强 for 循环；部分实现 `Serializable`、`Cloneable`。

## 原理

### 体系结构

```
Iterable
  └── Collection
        ├── List      → ArrayList, LinkedList, Vector
        ├── Set       → HashSet, LinkedHashSet, TreeSet
        └── Queue     → PriorityQueue, ArrayDeque
                              └── Deque
Map → HashMap, LinkedHashMap, TreeMap, Hashtable, ConcurrentHashMap
```

### 底层结构与复杂度

| 实现类 | 底层结构 | 查询 | 插入/删除 | 有序性 | 线程安全 |
|--------|----------|------|-----------|--------|----------|
| `ArrayList` | 动态数组 | O(1) 随机访问 | 尾部 O(1)，中间 O(n) | 插入顺序 | 否 |
| `LinkedList` | 双向链表 | O(n) | 头尾 O(1)，已知节点 O(1) | 插入顺序 | 否 |
| `HashMap` | 数组 + 链表/红黑树 | 平均 O(1) | 平均 O(1) | 无序 | 否 |
| `LinkedHashMap` | HashMap + 双向链表 | 平均 O(1) | 平均 O(1) | 插入顺序或访问顺序 | 否 |
| `TreeMap` | 红黑树 | O(log n) | O(log n) | 键排序 | 否 |
| `HashSet` | 委托 `HashMap` | 平均 O(1) | 平均 O(1) | 无序 | 否 |
| `TreeSet` | 委托 `TreeMap` | O(log n) | O(log n) | 排序 | 否 |
| `PriorityQueue` | 二叉堆（数组） | 堆顶 O(1) | 入队/出队 O(log n) | 按优先级 | 否 |

### 三条核心设计原则

1. **接口与实现分离**：面向 `List`、`Set`、`Map` 编程，便于替换实现。
2. **底层结构决定性能边界**：数组适合随机访问；链表适合头尾插入；哈希表适合键值查找；树适合有序范围查询。
3. **fail-fast 与 fail-safe**：
   - `ArrayList`、`HashMap` 等在迭代过程中结构被修改会抛 `ConcurrentModificationException`（fail-fast）。
   - `CopyOnWriteArrayList`、`ConcurrentHashMap` 迭代器反映创建时的快照或弱一致视图（fail-safe / 弱一致）。

### 关键机制摘要

1. **HashMap 寻址**：`(n - 1) & hash(key)`，其中 `hash = key.hashCode() ^ (key.hashCode() >>> 16)`，减少高位参与不足导致的碰撞。
2. **HashMap 树化**：单桶链表长度 ≥ 8 且数组长度 ≥ 64 时链表转红黑树；树节点 ≤ 6 时退化为链表。
3. **ArrayList 扩容**：默认初始容量 10（首次 add 时分配）；扩容为 `oldCapacity + (oldCapacity >> 1)`，即约 1.5 倍；涉及数组拷贝。
4. **TreeMap 排序**：按 `Comparable` 自然序或构造时传入的 `Comparator`；键不能为 `null`（JDK 7+）。

## 应用场景

| 场景 | 推荐实现 | 原因 |
|------|----------|------|
| 按索引随机读写、遍历为主 | `ArrayList` | 连续内存，缓存友好 |
| 频繁头尾插入删除 | `LinkedList` 或 `ArrayDeque` | 链表头尾 O(1)；双端队列语义更清晰 |
| 键值缓存、索引映射 | `HashMap` | 平均 O(1) 查找 |
| 需要 LRU 或插入顺序 | `LinkedHashMap` | 维护双向链表；可设 `accessOrder=true` 实现 LRU |
| 需要键排序或范围查询 | `TreeMap` | 红黑树，支持 `subMap`、`headMap` |
| 元素去重 | `HashSet`（无序）或 `TreeSet`（有序） | 基于 Map 的键唯一性 |
| TopK、任务调度 | `PriorityQueue` | 小顶堆，堆顶为最值 |
| 高并发读写 Map | `ConcurrentHashMap` | 见 JUC 文档 |
| 算法题：两数之和、频次统计 | `HashMap` | 键值查找与计数 |
| 算法题：滑动窗口最值 | `TreeMap` 或单调队列 | 有序统计或 O(1) 均摊 |

## 高频面试点

1. **HashMap**：哈希寻址、冲突处理、树化/退化、扩容、JDK 7 头插 vs JDK 8 尾插、`hashCode`/`equals` 契约。
2. **List**：`ArrayList` 与 `LinkedList` 的复杂度差异、扩容成本、为何业务中 `ArrayList` 更常用。
3. **Tree**：`TreeMap`/`TreeSet` 红黑树、`Comparable` vs `Comparator`、与 `HashMap` 的选型边界。
4. **Set**：`HashSet` 如何保证不重复（底层 `HashMap`，元素存于 key，value 为固定 `PRESENT` 对象）。
5. **equals / hashCode**：重写 `equals` 必须重写 `hashCode`；否则 Hash 集合行为异常。
6. **不可变集合**：`Collections.unmodifiableXxx` 与 `List.of`/`Map.of`（JDK 9+）的区别。
7. **Queue**：`PriorityQueue` 非线程安全、非 FIFO；`ArrayDeque` 作为栈/队列的用法。

## 面试官视角：集合框架考题设计

### 考察规则

1. **基础题**考察接口边界，要求候选人能说明 `List`/`Set`/`Map`/`Queue` 的语义差异和典型实现。
2. **原理题**考察底层结构与复杂度，要求候选人能解释 HashMap 寻址、扩容、树化及 ArrayList 扩容。
3. **选型题**考察工程取舍，要求候选人能根据访问模式、有序性、并发性选择实现。
4. **契约题**考察 `equals`/`hashCode`/`Comparable` 一致性，要求候选人能说明违反契约的后果。
5. **算法题**考察集合作为建模工具的能力，要求候选人能选择合适容器并分析复杂度。

### 基础理解题

1. **`Collection` 和 `Map` 的区别是什么？**
   - 考察点：是否理解两条独立继承线及各自语义。
   - 追问方向：`Map` 的 key 能否重复？value 能否重复？
   - 参考回答：`Collection` 存储单个元素，`Map` 存储键值对。`Map` 的 key 唯一，value 可重复；一个 key 只对应一个 value。`Map` 不继承 `Collection`，但可通过 `entrySet()`、`keySet()`、`values()` 获得集合视图。

2. **`List`、`Set`、`Queue` 分别保证什么特性？**
   - 考察点：是否区分有序、唯一、FIFO 三个维度。
   - 追问方向：`Set` 是否一定无序？
   - 参考回答：`List` 有序且可重复，支持按索引访问。`Set` 元素不重复，是否有序取决于实现：`HashSet` 无序，`LinkedHashSet` 保持插入顺序，`TreeSet` 按比较器排序。`Queue` 按特定规则出队，通常 FIFO；`PriorityQueue` 按优先级而非插入顺序出队。

3. **`HashSet` 如何保证元素不重复？**
   - 考察点：是否知道底层委托 `HashMap`，以及 `PRESENT` 占位对象。
   - 追问方向：如果两个对象 `equals` 相等但 `hashCode` 不同会怎样？
   - 参考回答：`HashSet` 内部维护一个 `HashMap`，元素作为 key 存入，value 是固定的 `Object PRESENT` 哨兵对象。添加时调用 `map.put(e, PRESENT)`，相同 key（按 `hashCode` + `equals`）只会覆盖而不会新增。若 `equals` 相等但 `hashCode` 不同，两个对象会落入不同桶，`HashSet` 会存入两个元素，违反 Set 语义，因此重写 `equals` 必须重写 `hashCode`。

4. **重写 `equals` 为什么必须重写 `hashCode`？**
   - 考察点：是否理解 Hash 集合的契约：`equals` 相等则 `hashCode` 必须相等。
   - 追问方向：只重写 `hashCode` 不重写 `equals` 有什么问题？
   - 参考回答：Hash 集合先用 `hashCode` 定位桶，再用 `equals` 比较。若两对象 `equals` 相等但 `hashCode` 不同，会被放入不同桶，导致 HashMap/HashSet 出现重复键或重复元素，且 `get` 可能找不到。规范要求：相等对象必须有相同 hashCode；hashCode 相同的对象不一定相等。

### HashMap 原理题

1. **HashMap 的 put 流程是什么？**
   - 考察点：hash 计算、寻址、冲突处理、树化判断、扩容触发。
   - 追问方向：JDK 8 为什么把头插改为尾插？
   - 参考回答：put 时先计算 key 的 hash，用 `(n-1) & hash` 定位桶。桶为空则 CAS/直接放入节点；不为空则遍历链表或红黑树，key 相等则覆盖 value，否则追加。链表长度 ≥ 8 且数组长度 ≥ 64 时树化。元素数超过 `capacity * loadFactor`（默认 0.75）时扩容为 2 倍并重哈希。JDK 8 改为尾插，是为避免并发扩容场景下头插导致链表环（JDK 7 并发 resize 的已知问题）；HashMap 本身仍非线程安全。

2. **HashMap 何时树化？阈值 8 和 6 的设计动机是什么？**
   - 考察点：是否理解泊松分布与红黑树空间/时间权衡。
   - 追问方向：为什么树化还要求数组长度 ≥ 64？
   - 参考回答：单桶链表长度 ≥ 8 时转红黑树，≤ 6 时退化为链表。阈值 8 基于泊松分布：在良好 hash 下，单桶长度达到 8 的概率极低（约 0.00000006），出现则说明 hash 冲突严重或遭受攻击。树化有额外内存开销，仅在冲突极端时使用。要求数组长度 ≥ 64 是为避免小表频繁树化/退化；小表优先扩容分散冲突。

3. **HashMap 的 loadFactor 为什么是 0.75？**
   - 考察点：是否理解时间复杂度与空间利用率的权衡。
   - 追问方向：loadFactor 设为 1.0 会怎样？
   - 参考回答：0.75 是经验值，在空间利用率与碰撞概率之间折中。loadFactor 越大，扩容越少、内存利用率越高，但链表/树更长、查询变慢。设为 1.0 会减少扩容次数，但碰撞显著增加，平均查询性能下降。

4. **HashMap 扩容时 rehash 做了什么？**
   - 考察点：是否理解 2 倍扩容与 `(e.hash & oldCap) == 0` 的位运算优化。
   - 追问方向：为什么容量必须是 2 的幂？
   - 参考回答：扩容为 2 倍后，每个元素要么留在原索引 `i`，要么移到 `i + oldCap`，可通过 `e.hash & oldCap` 判断，无需重新取模。容量为 2 的幂时，`(n-1) & hash` 等价于高效取模且分布均匀；非 2 的幂会导致某些桶永远为空，hash 分布不均。

5. **`HashMap` 允许 null key 和 null value 吗？`ConcurrentHashMap` 呢？**
   - 考察点：是否理解 null 在并发语义下的歧义。
   - 追问方向：为什么 `ConcurrentHashMap` 不允许 null key/value？
   - 参考回答：`HashMap` 允许一个 null key 和多个 null value。`ConcurrentHashMap` 不允许 null key 和 null value，因为 `get(key)` 返回 null 无法区分「键不存在」与「值为 null」，在并发且无锁读场景下会产生歧义。`Hashtable` 也不允许 null。

### List 实现题

1. **`ArrayList` 和 `LinkedList` 的底层结构与复杂度差异？**
   - 考察点：是否理解数组 vs 链表及各自适用场景。
   - 追问方向：什么情况下 `LinkedList` 比 `ArrayList` 更慢？
   - 参考回答：`ArrayList` 基于动态数组，随机访问 O(1)，尾部追加均摊 O(1)，中间插入/删除 O(n)（需移动元素）。`LinkedList` 基于双向链表，随机访问 O(n)，头尾插入/删除 O(1)。实际业务中 `ArrayList` 更常用，因为连续内存缓存命中率高、常数因子小；`LinkedList` 每个节点有额外指针开销，且随机访问频繁时性能差。

2. **`ArrayList` 扩容策略如何影响性能？**
   - 考察点：是否理解 1.5 倍扩容、数组拷贝成本、预分配容量。
   - 追问方向：已知要插入 10000 个元素，如何减少扩容次数？
   - 参考回答：默认初始容量 0，首次 add 分配 10；之后每次扩容为 `old + old/2`，涉及新数组分配与 `System.arraycopy`。频繁扩容会产生多次拷贝。已知大小时应使用 `new ArrayList<>(expectedSize)` 一次性分配，将扩容次数降为 0 或 1 次。

3. **`Vector` 和 `ArrayList` 的区别？现在还会用 `Vector` 吗？**
   - 考察点：是否理解早期线程安全设计与性能代价。
   - 追问方向：需要线程安全的 List 应选什么？
   - 参考回答：`Vector` 方法用 `synchronized` 修饰，线程安全但锁粒度粗、并发性能差。`ArrayList` 非线程安全。现代工程不推荐使用 `Vector`；需要线程安全时用 `Collections.synchronizedList`（读写都加锁）或 `CopyOnWriteArrayList`（读多写少），或外部用锁/并发工具控制。

### Tree 与排序题

1. **`TreeMap` 和 `HashMap` 的选型边界？**
   - 考察点：是否理解 O(1) vs O(log n) 及有序性需求。
   - 追问方向：需要按 key 范围查询 `[low, high)` 时用哪个？
   - 参考回答：只需键值存取、不要求排序时用 `HashMap`，平均 O(1)。需要 key 排序、范围查询（`subMap`/`headMap`/`tailMap`）、取最值/相邻键时用 `TreeMap`，操作 O(log n)。`TreeMap` 要求 key 实现 `Comparable` 或构造时传入 `Comparator`；`HashMap` 允许 null key（一个）。

2. **`Comparable` 和 `Comparator` 的区别？**
   - 考察点：自然排序 vs 外部比较器、对类设计的侵入性。
   - 追问方向：`TreeSet` 中 `compare` 返回 0 但 `equals` 为 false 会怎样？
   - 参考回答：`Comparable` 是元素内部比较（`compareTo`），一种自然顺序。`Comparator` 是外部策略，可灵活切换排序规则。`TreeSet`/`TreeMap` 只依赖 `compare`/`compareTo` 判断相等性：若 `compare` 返回 0 则视为同一元素，即使 `equals` 为 false 也不会重复存储，可能导致「逻辑上不同但树中只存一个」的问题，因此比较器应保证与 `equals` 一致。

3. **红黑树的特点？为什么 HashMap 用红黑树而不是 AVL 树？**
   - 考察点：是否理解平衡二叉搜索树的旋转代价与查询性能。
   - 追问方向：红黑树的五条性质是什么？
   - 参考回答：红黑树是近似平衡的二叉搜索树，保证最长路径不超过最短路径的 2 倍，查找/插入/删除均为 O(log n)。相比 AVL 树（严格平衡），红黑树插入/删除旋转次数更少，写操作常数更小；HashMap 中树化场景冲突写入较多，红黑树综合性能更优。

### Queue 与 Deque 题

1. **`PriorityQueue` 是堆还是完全有序的？**
   - 考察点：是否理解堆只保证堆顶最值，不保证迭代顺序。
   - 追问方向：如何按优先级顺序遍历所有元素？
   - 参考回答：`PriorityQueue` 基于二叉小顶堆（默认），堆顶是最小元素，出队 O(log n)。它不满足 FIFO，也不保证迭代器顺序完全按优先级；迭代顺序是堆的内部数组布局。如需有序遍历，应反复 `poll()` 或使用 `TreeSet`。

2. **`ArrayDeque` 与 `Stack` 类的关系？**
   - 考察点：是否知道 `Stack` 继承 `Vector` 已过时，推荐 `ArrayDeque`。
   - 追问方向：用 `ArrayDeque` 实现队列和栈分别调用什么方法？
   - 参考回答：`Stack` 继承 `Vector`，同步开销大，官方推荐用 `ArrayDeque`。作栈：`push`/`pop`（或 `addFirst`/`removeFirst`）。作队列：`offer`/`poll`（FIFO 用 `offerLast`/`pollFirst`）。`ArrayDeque` 不允许 null 元素。

### 选型与场景设计题

1. **实现一个 LRU 缓存（容量 N），选什么数据结构？**
   - 考察点：是否理解 `LinkedHashMap` 的 `accessOrder` 或「HashMap + 双向链表」手写方案。
   - 追问方向：get/put 的时间复杂度？并发场景如何改造？
   - 参考回答：使用 `LinkedHashMap(accessOrder=true)`，重写 `removeEldestEntry` 在 size > N 时返回 true 删除最久未访问条目。get/put 均 O(1)。并发场景需加锁或改用 `Caffeine`/`Guava Cache` 等成熟缓存库，不直接用非线程安全的 `LinkedHashMap`。

2. **统计一段文本中单词出现频次，按频次降序输出 Top 10，如何实现？**
   - 考察点：`HashMap` 计数 + `PriorityQueue` 或排序。
   - 追问方向：单词量 100 万、只要 Top 10，如何优化？
   - 参考回答：先用 `HashMap<String, Integer>` 统计频次 O(n)。再用大小为 10 的小顶堆，遍历 map 的 entry，维护频次最高的 10 个，复杂度 O(m log 10)，m 为不同单词数。若 m 较小也可直接排序 O(m log m)。

3. **需要线程安全的 Map，选 `Hashtable`、`Collections.synchronizedMap` 还是 `ConcurrentHashMap`？**
   - 考察点：是否理解锁粒度与并发读性能。
   - 追问方向：读多写少和写多读少分别怎么选？
   - 参考回答：优先 `ConcurrentHashMap`：JDK 8 读无锁、写桶级锁，并发度高。`Hashtable` 和 `synchronizedMap` 对整个表加锁，并发性能差，仅适合极低并发或遗留兼容。读多写少且需 List 快照时用 `CopyOnWrite` 系列；Map 场景仍首选 `ConcurrentHashMap`。

### 契约与陷阱题

1. **以下代码输出什么？如何修复？**
   ```java
   Map<String, Integer> map = new HashMap<>();
   map.put("a", 1);
   Integer v = map.get("a");
   v = 2;
   System.out.println(map.get("a"));
   ```
   - 考察点：是否理解 Map 存的是引用，修改取出对象会影响 Map 内容（若对象可变）。
   - 追问方向：若 value 是自定义 mutable 对象，如何避免副作用？
   - 参考回答：输出 2。`get` 返回的是 value 对象的引用，对 `Integer` 来说 `v = 2` 是重新赋值局部变量（Integer 不可变），不影响 Map。若 value 是可变对象（如 `List`），通过引用修改会改变 Map 中的值。修复方式：存入不可变对象、防御性拷贝、或封装访问接口。

2. **在 for-each 中删除 `ArrayList` 元素会怎样？正确做法？**
   - 考察点：fail-fast 机制与 `Iterator.remove()`。
   - 追问方向：`CopyOnWriteArrayList` 中直接 remove 可以吗？
   - 参考回答：增强 for 底层用迭代器，直接 `list.remove(i)` 会修改 modCount，迭代器检测到结构变化抛 `ConcurrentModificationException`。正确做法：使用 `Iterator.remove()`，或倒序 for 循环删除，或使用 `removeIf`。`CopyOnWriteArrayList` 的迭代器是快照，不支持 `Iterator.remove()`，但可以调用其 `remove()` 方法（会复制新数组）。

3. **`Arrays.asList()` 返回的 List 有什么限制？**
   - 考察点：是否理解固定大小列表与底层数组共享。
   - 追问方向：`list.add()` 和 `list.set()` 分别会怎样？
   - 参考回答：`Arrays.asList()` 返回固定大小的 `List`，不能 add/remove，否则抛 `UnsupportedOperationException`。可以 set，且修改会反映到原数组。需要可变 List 时使用 `new ArrayList<>(Arrays.asList(...))`。

### 算法建模题（集合选型）

1. **两数之和：给定数组和目标值，找两数下标。**
   - 考察点：能否用 `HashMap` 将 O(n²) 降为 O(n)。
   - 参考回答：遍历数组，对每个 `nums[i]`，检查 `target - nums[i]` 是否在 map 中；不在则 `map.put(nums[i], i)`。一次遍历 O(n)，空间 O(n)。

2. **合并两个有序链表。**
   - 考察点：链表操作或借助 `PriorityQueue`。
   - 参考回答：双指针迭代合并，O(m+n) 时间 O(1) 额外空间。若合并 K 个有序链表，用大小为 K 的 `PriorityQueue` 存各链表头，每次取最小节点接出，O(N log K)。

## 延伸问题

1. **HashMap 何时树化？阈值设计动机是什么？**
   - 参考回答：见上文「HashMap 何时树化」；核心规则：链表长度 ≥ 8 且数组长度 ≥ 64 时树化；≤ 6 时退化；8/6 间距防止频繁切换。

2. **ArrayList 扩容策略如何影响性能？**
   - 参考回答：见上文「ArrayList 扩容策略」；核心规则：1.5 倍扩容 + 数组拷贝；已知容量时用带参构造预分配。

3. **`LinkedHashMap` 如何实现 LRU？与 `WeakHashMap`、`IdentityHashMap` 的区别？**
   - 参考回答：`LinkedHashMap` 在 `HashMap` 外维护双向链表，`accessOrder=true` 时 get/put 会把节点移到队尾，队头为最久未用。`WeakHashMap` 的 key 是弱引用，GC 后 entry 自动移除，适合缓存键生命周期由外部管理的场景。`IdentityHashMap` 用 `==` 而非 `equals` 比较 key，适合需要对象身份语义的场景（如图形对象去重）。

4. **`HashMap` 和 `ConcurrentHashMap` 在 JDK 7 和 JDK 8 的实现差异？**
   - 参考回答：JDK 7 的 `ConcurrentHashMap` 用 Segment 分段锁；JDK 8 改为 CAS + 桶级 `synchronized`，结构与 `HashMap` 类似并支持多线程协助扩容。`HashMap` JDK 7 是数组+链表头插；JDK 8 是数组+链表/红黑树尾插。

5. **为什么重写 `hashCode` 推荐使用 31 作为乘数？**
   - 参考回答：31 是奇质数，减少 hash 碰撞；`31 * i` 可优化为 `(i << 5) - i`，JVM 乘法优化效率高；经验上字符串等对象的 hash 分布较好。

## 回答策略（候选人视角）

1. **先结论后原理**：例如「业务默认用 `ArrayList`」，再补充复杂度与缓存友好性。
2. **带复杂度**：回答必须包含时间/空间复杂度，否则深度不足。
3. **带边界条件**：如 null 支持、线程安全、fail-fast、容量上限。
4. **带 JDK 版本差异**：HashMap 头插/尾插、ConcurrentHashMap Segment vs 桶锁，是加分项。
5. **能落到场景**：LRU 用 `LinkedHashMap`，TopK 用堆，频次统计用 `HashMap`，并发用 `ConcurrentHashMap`。
