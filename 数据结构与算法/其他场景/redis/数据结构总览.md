# Redis - 数据结构总览

## 定义

Redis 提供多种数据结构以支持不同访问模式与性能目标。

## 原理

根据读写特征、排序需求、去重需求和空间效率选择结构。

## 应用场景

1. 缓存。
2. 排行榜。
3. 去重与过滤。
4. 地理位置检索。

## 高频面试点

1. String、Hash、List、Set、ZSet 的适用边界。
2. Bloom Filter 的误判特性与使用边界。
3. ZSet 与 SkipList 的关系。
4. Geohash 的编码思想与附近检索能力。

## 高频问题回答

### 1) String、Hash、List、Set、ZSet 的适用边界

1. String：缓存单值、计数器、分布式锁 token。
2. Hash：对象属性聚合存储，适合字段更新频繁场景。
3. List：消息队列、时间线，侧重头尾操作。
4. Set：去重集合、标签集合，强调唯一性。
5. ZSet：有序集合，适合排行榜、延时任务、范围检索。

### 2) Bloom Filter 的误判特性与使用边界

1. 结论：Bloom Filter 只会“误判存在”，不会“误判不存在”。
2. 使用边界：适合做存在性预过滤，不适合做最终一致性判断。
3. 设计规则：位图大小和哈希函数数量需根据目标误判率计算。

### 3) ZSet 与 SkipList 的关系

1. Redis ZSet 常用实现由哈希表 + SkipList 组成。
2. 哈希表负责按 member 快速定位。
3. SkipList 负责按 score 有序检索和范围查询。

### 4) Geohash 的编码思想与附近检索能力

1. Geohash 把经纬度编码为字符串前缀。
2. 前缀越接近，空间位置通常越接近。
3. 可用于附近检索，但边界区域需补偿查询。

## 延伸问题与回答

### 1) 如何结合业务 QPS 与内存预算选型？

业务规则：

1. 先定义目标：单 key QPS、总 QPS、P99 延迟、最大内存上限。
2. 高频读单值优先 String；对象字段更新优先 Hash。
3. 排序与范围查询优先 ZSet；纯去重优先 Set。
4. 高基数存在性过滤优先 Bloom Filter 或 Bitmap。
5. 对大 key 设置拆分规则：按业务维度分片（如 userId、date）。

### 2) 如何设计过期策略与淘汰策略避免雪崩？

业务规则：

1. TTL 必须加随机抖动（例如基础 TTL + 0~20% 随机值）。
2. 热点 key 必须采用逻辑过期 + 后台刷新，避免同一时刻失效。
3. 缓存重建必须加互斥控制（分布式锁或单飞机制）。
4. 淘汰策略按业务选择：`allkeys-lru` 或 `allkeys-lfu` 优先。
5. 对下游依赖配置限流与降级，避免缓存失效时流量打爆数据库。

## Spring Boot + Redisson 分布式锁最佳实践

### 设计目标

1. 保证同一业务键在同一时刻最多一个线程执行关键区。
2. 业务异常时锁能自动释放。
3. 服务节点故障时锁不会永久占用。

### 关键规则（必须执行）

1. 锁 key 必须带业务前缀与唯一业务标识（例如 `lock:order:create:{orderId}`）。
2. 优先使用 `tryLock(waitTime, leaseTime, unit)`，禁止无限阻塞。
3. 释放锁前必须判断 `isHeldByCurrentThread()`。
4. 锁内代码必须幂等，避免重复执行造成数据污染。
5. 锁只保护“关键写操作”，禁止把远程慢调用全部放入锁内。
6. 为锁操作记录日志与指标：获取成功率、等待时长、持有时长、失败次数。

### Spring Boot 配置示例

```yaml
spring:
  redis:
    host: 127.0.0.1
    port: 6379

redisson:
  single-server-config:
    address: "redis://127.0.0.1:6379"
    connectionPoolSize: 64
    connectionMinimumIdleSize: 24
```

```java
// RedissonConfig.java
import org.redisson.Redisson;
import org.redisson.api.RedissonClient;
import org.redisson.config.Config;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class RedissonConfig {

    @Bean(destroyMethod = "shutdown")
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer().setAddress("redis://127.0.0.1:6379");
        return Redisson.create(config);
    }
}
```

### 业务代码示例（订单创建防重）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Slf4j
@Service
@RequiredArgsConstructor
public class OrderCreateService {

    private final RedissonClient redissonClient;

    public void createOrder(Long userId, Long orderId) {
        String lockKey = "lock:order:create:" + orderId;
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            locked = lock.tryLock(300, 10, TimeUnit.MILLISECONDS);
            if (!locked) {
                throw new IllegalStateException("系统繁忙，请稍后重试");
            }

            // 关键区：查询是否已创建 -> 创建订单 -> 写审计日志
            // 这里必须实现幂等校验（例如唯一索引或业务幂等表）
            doCreateOrder(userId, orderId);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IllegalStateException("线程中断，订单创建失败", e);
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    private void doCreateOrder(Long userId, Long orderId) {
        log.info("create order, userId={}, orderId={}", userId, orderId);
    }
}
```

### 常见错误

1. 未设置 `leaseTime`，业务卡死时锁长期占用。
2. 捕获异常后未 `unlock`，导致锁泄漏。
3. 锁粒度过大，系统吞吐下降。
4. 只加锁不做幂等，重试后仍可能重复写入。
