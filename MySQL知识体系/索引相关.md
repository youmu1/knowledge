# 索引相关

## 定义

MySQL（InnoDB）索引是有序数据结构，用于加速检索并参与行锁粒度控制。InnoDB 以 **B+Tree** 为主（聚簇索引 + 二级索引），辅以 Adaptive Hash、Full-text 等。索引设计直接影响查询路径、回表次数与并发锁范围。

## 原理

### 索引结构速查

| 类型 | 存储 | 特点 | 典型用途 |
|------|------|------|----------|
| 聚簇索引 | 叶子节点存完整行 | 表数据按主键顺序组织，每表一个 | 主键查询、范围扫描 |
| 二级索引（非聚簇） | 叶子存索引列 + 主键 | 查非主键列需回表 | 普通列条件、排序 |
| 覆盖索引 | 二级索引含查询全部列 | Extra: Using index，免回表 | 高频查询列组合 |
| Hash（Adaptive） | 内存自适应 | 等值加速，不可控、非持久 | InnoDB 热点页自动建 |
| Full-text | 倒排索引 | 分词、全文匹配 | 文本搜索 |

B+Tree 结构细节见 [索引结构与 B+Tree](../数据结构与算法/其他场景/mysql/索引结构与BPlusTree.md)；Hash 对比见 [Hash 索引对比](../数据结构与算法/其他场景/mysql/Hash索引对比.md)。

### 为什么用 B+Tree 而非 B-Tree / Hash / 红黑树 / SkipList

| 结构 | 不选或次要原因 |
|------|----------------|
| B-Tree | 非叶子也存数据，单页容纳 key 少，IO 次数高 |
| Hash | 不支持范围查询与排序；冲突与扩容成本 |
| 红黑树 | 树高高于 B+Tree，磁盘 IO 多；范围查询需中序遍历 |
| SkipList | 内存结构友好（Redis ZSet）；磁盘页式存储 B+ 更成熟 |

Redis ZSet 用 SkipList 因 **纯内存、实现简单、范围操作方便**；MySQL 磁盘场景 B+ 叶子链表 + 页分裂/合并工程成熟。

### 磁盘预读与 MRR

1. **磁盘预读**：InnoDB 按页（默认 16KB）读取，局部性原理使顺序扫描相邻页成本低。
2. **Buffer Pool**：热页缓存在内存，减少磁盘 IO。
3. **MRR（Multi-Range Read）**：二级索引扫描时，先把主键 id 收集排序，再顺序回表，减少随机 IO。相关参数：`optimizer_switch='mrr=on'`、`read_rnd_buffer_size`。

### 锁机制总表

| 锁 | 粒度 | 兼容性 | 作用 |
|----|------|--------|------|
| 表共享锁 S | 表 | 与 S 兼容，与 X 互斥 | `LOCK TABLES ... READ` |
| 表排他锁 X | 表 | 与所有互斥 | `LOCK TABLES ... WRITE` |
| 意向共享 IS | 表 | 表级「有行 S 锁」信号 | 加速表锁判断 |
| 意向排他 IX | 表 | 表级「有行 X 锁」信号 | 加速表锁判断 |
| MDL 共享 | 元数据 | DDL 与 DML 协调 | 读表结构 |
| MDL 排他 | 元数据 | 阻塞 DML | `ALTER TABLE` 等 DDL |
| 行共享锁 S | 行 | 读锁，与 S 兼容 | `LOCK IN SHARE MODE` |
| 行排他锁 X | 行 | 写锁 | `UPDATE/DELETE/SELECT FOR UPDATE` |
| 间隙锁 Gap | 索引间隙 | RR 下阻止插入 | 防幻读（当前读） |
| 临键锁 Next-Key | 行 + 前间隙 | RR 默认行锁 | 记录锁 +  gap |

**加锁规则（RR + 非唯一二级索引，简化）**：

1. 等值命中唯一索引 → 行锁。
2. 等值未命中 → 间隙锁。
3. 范围扫描 → 范围内 next-key lock。

### 最左前缀与索引优化

**最左前缀**：联合索引 `(a, b, c)` 可支持 `a`、`a,b`、`a,b,c` 前缀匹配；跳过左列则无法用索引排序/范围（可能走 index merge 或全表）。

**`WHERE b = 1 AND a = 1` 在 `(a,b,c)` 上能命中**：优化器会重排为 `a=1 AND b=1`，满足最左前缀。

| 优化手段 | 含义 | Extra 标志 |
|----------|------|------------|
| 索引覆盖 | 查询列全在索引中 | Using index |
| 索引下推 ICP | 存储引擎层过滤联合索引条件 | Using index condition |
| 减少回表 | 只查必要列或建覆盖索引 | rows 下降 |

### 索引失效常见规则（8 类）

| # | 场景 | 示例 |
|---|------|------|
| 1 | 对索引列用函数/表达式 | `WHERE DATE(create_time) = '2025-01-01'` |
| 2 | 隐式类型转换 | `varchar` 列与数字比较 |
| 3 | 左模糊 / 纯 `%` | `WHERE name LIKE '%张'` |
| 4 | OR 一侧无索引 | `WHERE a=1 OR b=1`（b 无索引） |
| 5 | 联合索引跳列 | 索引 `(a,b,c)` 仅 `WHERE b=1` |
| 6 | 优化器判定回表成本过高 | 大比例 rows，可能选全表 |
| 7 | 不等于 / NOT IN（视版本与选择性） | `WHERE status != 1` |
| 8 | 字符集/排序规则不一致 | join 两列 collation 不同 |

**同样条件有时走索引有时不走**：统计信息变化、数据量变化、优化器成本估算不同 → 用 `EXPLAIN` + `optimizer_trace` 验证。

### 死锁检测

```sql
SHOW ENGINE INNODB STATUS\G   -- 看 LATEST DETECTED DEADLOCK
SELECT * FROM performance_schema.data_locks;
SELECT * FROM performance_schema.data_lock_waits;
```

## 应用场景

1. 高频 WHERE / ORDER BY / JOIN 列建联合索引。
2. 读多写少列表用覆盖索引避免回表。
3. 范围更新用合适索引减少锁范围。
4. 排查慢 SQL 时对照 EXPLAIN 与锁等待。

## 面试官视角

### 考察规则

1. **结构题**考察 B+、聚簇/二级、覆盖/回表。
2. **优化题**考察最左前缀、失效条件、ICP。
3. **锁题**考察 next-key、幻读、死锁。
4. **排障题**考察 EXPLAIN + InnoDB STATUS。

### 基础题

1. **聚簇索引和非聚簇索引的区别？**
   - 考察点：数据物理顺序、是否回表。
   - 参考回答：InnoDB 聚簇索引叶子存整行，表即索引；二级索引叶子存索引列和主键，非覆盖查询需拿主键回聚簇索引取行。

2. **`a,b,c` 联合索引，`WHERE b=1 AND a=1` 能用索引吗？**
   - 考察点：优化器重排 + 最左前缀。
   - 参考回答：能。等价于 `a=1 AND b=1`，满足最左前缀。仅 `WHERE b=1` 不能完整利用联合索引。

3. **MVCC 能完全解决幻读吗？**
   - 考察点：快照读 vs 当前读。
   - 参考回答：快照读（普通 SELECT）通过 Read View 避免看到新插入行；当前读（`FOR UPDATE`）在 RR 下用 next-key lock 阻塞间隙插入。完全避免幻读需当前读加锁。

## 实战案例

### 案例 1：对索引列做函数导致全表扫描

- **现象**：`WHERE DATE(create_time) = '2025-05-01'` 慢，`type=ALL`。
- **定位**：`EXPLAIN` 见 `key=NULL`，`rows` 接近全表。
- **根因**：对 `create_time` 施加函数，无法使用 B+Tree 有序性。
- **解法**：改写为范围查询 `create_time >= '2025-05-01' AND create_time < '2025-05-02'`，或生成列 + 索引。

### 案例 2：RR 下当前读与间隙锁

- **现象**：事务 A `SELECT * FROM orders WHERE id > 10 AND id < 20 FOR UPDATE` 后，事务 B 插入 `id=15` 阻塞。
- **定位**：`SHOW ENGINE INNODB STATUS` 见 gap lock。
- **根因**：RR + 当前读对区间加 next-key lock，防止幻读。
- **解法**：业务预期行为；若需高并发插入可评估 RC 隔离级别或缩小锁定范围。

## 一分钟速记

1. InnoDB 主键即聚簇索引，二级索引叶子存主键，非覆盖需回表。
2. 联合索引最左前缀；优化器可重排等值条件。
3. 覆盖索引 → Using index；ICP → 引擎层过滤。
4. 失效：函数、隐式转换、左模糊、OR 无索引、跳列。
5. RR 当前读用 next-key lock；快照读靠 MVCC。
6. 死锁：`SHOW ENGINE INNODB STATUS` + `data_lock_waits`。
7. MRR：先排序主键再回表，减随机 IO。
8. B+ 细节见 algo 目录，本篇管锁与优化规则。
