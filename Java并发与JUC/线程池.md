# 线程池（Thread Pool）

## 1. 线程池的作用

线程池用于统一管理线程资源，核心目标如下：

1. 复用线程，降低频繁创建/销毁线程的开销。
2. 控制并发度，防止线程数量无限增长。
3. 通过队列与拒绝策略实现背压与降级。
4. 统一线程命名、异常处理、监控和关闭流程。

---

## 2. JUC 核心类型

线程池相关的核心类型主要位于 `java.util.concurrent`：

- `Executor`：任务执行的顶层接口。
- `ExecutorService`：扩展了生命周期管理（提交、关闭、等待终止）。
- `ThreadPoolExecutor`：最常用、可精细配置的线程池实现。
- `ScheduledExecutorService`：用于延迟任务和周期任务。

---

## 3. ThreadPoolExecutor 核心参数

`ThreadPoolExecutor` 构造参数决定了线程池行为：

1. `corePoolSize`：核心线程数。
2. `maximumPoolSize`：最大线程数。
3. `keepAliveTime`：非核心线程空闲回收时间。
4. `workQueue`：任务等待队列。
5. `threadFactory`：线程创建工厂（建议自定义线程名）。
6. `RejectedExecutionHandler`：拒绝策略。

### 任务处理规则（简化）

1. 线程数小于 `corePoolSize`：直接创建线程执行任务。
2. 达到核心线程数：任务入队。
3. 队列满且线程数小于 `maximumPoolSize`：继续创建线程。
4. 队列满且线程数达到上限：触发拒绝策略。

---

## 4. 常见队列与拒绝策略

### 4.1 工作队列

- `ArrayBlockingQueue`：有界队列，容量固定，推荐用于可控场景。
- `LinkedBlockingQueue`：默认容量很大（接近无界），风险是任务堆积。
- `SynchronousQueue`：不存储任务，任务直接交给线程处理。

### 4.2 拒绝策略

- `AbortPolicy`：抛出异常（默认）。
- `CallerRunsPolicy`：提交线程自己执行任务（形成背压）。
- `DiscardPolicy`：直接丢弃新任务。
- `DiscardOldestPolicy`：丢弃队列最旧任务，再尝试提交。

---

## 5. 常见案例

## 案例 A：CPU 密集型任务（加密、计算、规则匹配）

配置建议：

1. 线程数接近 CPU 核心数（通常为 `N` 或 `N+1`）。
2. 使用有界队列，避免任务无限排队。
3. 优先选择快速失败或可观测的拒绝策略。

## 案例 B：IO 密集型任务（HTTP、数据库、文件）

配置建议：

1. 线程数可高于 CPU 核心数。
2. 必须设置有界队列与超时机制。
3. 对慢依赖设置降级和隔离，避免线程池被长期占满。

## 案例 C：异步事件处理（通知、审计、埋点）

配置建议：

1. 业务线程池与公共线程池隔离。
2. 线程命名包含业务前缀，便于排查。
3. 记录拒绝次数、队列长度、任务耗时。

---

## 6. 最佳实践（可执行清单）

1. 优先显式使用 `ThreadPoolExecutor`，避免直接依赖 `Executors` 默认工厂。
2. 队列优先有界，容量由压测结果决定。
3. 线程池按业务域隔离，避免互相拖垮。
4. 自定义 `ThreadFactory`，统一线程命名格式。
5. 明确拒绝策略，并与业务规则对齐（是否允许丢任务）。
6. 所有外部调用必须配置超时，避免线程永久阻塞。
7. 完整处理异常：记录日志、上报指标、可选重试。
8. 应用退出时执行优雅关闭（`shutdown` + `awaitTermination`）。
9. 监控最少包含：活跃线程数、队列长度、完成任务数、拒绝次数、任务耗时。

---

## 7. 示例代码（推荐模板）

```java
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class PoolExample {
    public static ExecutorService buildPool() {
        int core = 4;
        int max = 8;
        long keepAliveSeconds = 60L;
        int queueCapacity = 200;

        ThreadFactory factory = new ThreadFactory() {
            private final AtomicInteger idx = new AtomicInteger(1);
            @Override
            public Thread newThread(Runnable r) {
                Thread t = new Thread(r, "biz-pool-" + idx.getAndIncrement());
                t.setUncaughtExceptionHandler((th, ex) ->
                        System.err.println("线程异常: " + th.getName() + ", " + ex.getMessage()));
                return t;
            }
        };

        RejectedExecutionHandler rejectHandler = new ThreadPoolExecutor.CallerRunsPolicy();

        return new ThreadPoolExecutor(
                core,
                max,
                keepAliveSeconds,
                TimeUnit.SECONDS,
                new ArrayBlockingQueue<>(queueCapacity),
                factory,
                rejectHandler
        );
    }
}
```

## 8. Spring Boot 场景最佳实践与示例

### 8.1 配置独立业务线程池（推荐）

业务规则：

1. 使用 `@Configuration + @Bean` 显式声明线程池。
2. 线程池参数通过 `application.yml` 统一配置，禁止硬编码分散在业务代码中。
3. 业务线程池必须命名并隔离，禁止全部任务共用同一个线程池。
4. 队列容量必须为有界值。
5. 明确拒绝策略，且与业务可接受的降级策略一致。

```java
// AsyncPoolConfig.java
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.concurrent.ThreadPoolExecutor;

@Configuration
public class AsyncPoolConfig {

    @Bean(name = "orderAsyncExecutor")
    public ThreadPoolTaskExecutor orderAsyncExecutor(
            @Value("${app.async.order.core-size:4}") int coreSize,
            @Value("${app.async.order.max-size:8}") int maxSize,
            @Value("${app.async.order.queue-capacity:200}") int queueCapacity,
            @Value("${app.async.order.keep-alive-seconds:60}") int keepAliveSeconds) {

        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(coreSize);
        executor.setMaxPoolSize(maxSize);
        executor.setQueueCapacity(queueCapacity);
        executor.setKeepAliveSeconds(keepAliveSeconds);
        executor.setThreadNamePrefix("order-async-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(30);
        executor.initialize();
        return executor;
    }
}
```

```yaml
# application.yml
app:
  async:
    order:
      core-size: 4
      max-size: 8
      queue-capacity: 200
      keep-alive-seconds: 60
```

### 8.2 在服务层使用 @Async 绑定指定线程池

业务规则：

1. `@Async` 必须显式指定线程池 Bean 名称。
2. 异步方法返回值统一使用 `CompletableFuture` 或 `void`（根据场景选一种）。
3. 异步任务中的异常必须记录日志并上报监控。

```java
// AsyncExecutorEnableConfig.java
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;

@Configuration
@EnableAsync
public class AsyncExecutorEnableConfig {
}
```

```java
// OrderAsyncService.java
import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;

import java.util.concurrent.CompletableFuture;

@Slf4j
@Service
public class OrderAsyncService {

    @Async("orderAsyncExecutor")
    public CompletableFuture<Void> sendOrderCreatedMessage(Long orderId) {
        try {
            // 执行业务逻辑，例如通知、审计、回调等
            log.info("send order created message, orderId={}", orderId);
            return CompletableFuture.completedFuture(null);
        } catch (Exception ex) {
            log.error("async task failed, orderId={}", orderId, ex);
            return CompletableFuture.failedFuture(ex);
        }
    }
}
```

### 8.3 Spring Boot 场景补充建议

1. 对外部依赖调用必须设置超时（HTTP/DB/RPC），避免线程池阻塞。
2. 监控指标至少包括：活跃线程数、队列长度、任务拒绝次数、平均耗时。
3. 高优先级业务与低优先级业务必须使用独立线程池。
4. 关闭流程必须等待任务结束或超时退出，禁止直接强制停止。

---

## 9. 易错点

1. 使用无界队列导致内存膨胀与请求超时放大。
2. 忽略 `Future` 异常，任务失败但主流程无感知。
3. 线程池不关闭，导致应用无法优雅退出。
4. 多个业务共享同一个池，峰值互相影响。
