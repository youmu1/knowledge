# 简历项目经历库

这个目录用于存放简历中项目经历相关的内容，每个项目都使用 STAR 法则进行描述。

## 📁 目录结构

```
resume-projects/
├── README.md                      # 本文件
├── 账户缓存架构优化项目.md         # 分布式缓存优化项目
└── [其他项目].md                  # 待添加的项目
```

## 📋 项目模板

每个项目文档包含以下部分：

### 1. 项目基本信息
- 项目名称
- 技术栈
- 项目时间
- 角色定位

### 2. STAR 法则描述
- **Situation（背景）**：项目背景和遇到的问题
- **Task（任务）**：需要完成的目标
- **Action（行动）**：具体采取的技术方案和实施步骤
- **Result（结果）**：量化的成果和业务价值

### 3. 技术详解
- 架构设计
- 核心代码片段
- 关键技术点

### 4. 面试要点
- 技术亮点
- 可能的面试问题及答案

### 5. 延伸思考
- 可以进一步优化的点
- 相关技术学习资源

## 🎯 使用指南

### 简历撰写时
1. 根据岗位要求选择合适的项目
2. 从 STAR 描述中提取核心内容
3. 调整量化数据（如果与实际不符）
4. 简历空间有限时，使用简化版

### 面试准备时
1. 熟读完整的技术详解部分
2. 准备面试问题的答案
3. 准备实际代码演示（如果需要）
4. 思考延伸问题

### 版本控制
- 每次更新项目内容后，更新文档底部的"最后更新时间"
- 重大修改时在文档顶部添加版本记录

## 💡 撰写技巧

### 量化指标参考
- **性能提升**：响应时间降低 XX%、QPS 提升 X 倍
- **成本节约**：服务器减少 XX%、资源利用率提升 XX%
- **业务影响**：支撑日均 XX 次调用、服务 XX 万用户
- **稳定性**：线上运行 X 个月零故障、可用性达到 X 个 9

### 技术深度体现
- 对比多种技术方案，说明选型理由
- 深入理解底层原理和实现机制
- 考虑边界情况、异常处理、监控告警
- 关注性能、安全、可维护性等多个维度

### 业务价值突出
- 不仅要说技术实现，更要说业务价值
- 成本节约、用户体验、系统稳定性
- 支撑业务增长、提升团队效率

## 🔖 标签体系

- **业务影响**：高、中、低
