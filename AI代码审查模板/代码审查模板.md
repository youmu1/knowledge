# 代码审查模板

> 用于指导 AI 进行代码审查的标准模板

## 🔍 代码审查 Checklist

### 1. 代码质量
- [ ] 是否有编译错误或警告
- [ ] 代码是否符合项目编码规范
- [ ] 是否有明显的性能问题
- [ ] 是否有潜在的空指针异常
- [ ] 异常处理是否完善

### 2. 设计模式
- [ ] 是否可以使用设计模式优化
- [ ] 是否存在深层嵌套的 if-else
- [ ] 是否违反 SOLID 原则
- [ ] 代码是否易于扩展

### 3. 代码重复
- [ ] 是否存在重复代码块
- [ ] 是否可以提取公共方法
- [ ] 是否可以复用现有工具类

### 4. 可维护性
- [ ] 方法是否过长（建议 < 50 行）
- [ ] 类是否职责单一
- [ ] 变量命名是否清晰
- [ ] 注释是否充分（特别是业务规则）

### 5. 测试
- [ ] 是否易于编写单元测试
- [ ] 是否需要 Mock 过多依赖
- [ ] 边界条件是否考虑

## 📋 审查 Prompt 模板

### 基础审查
```
请审查以下代码，检查：
1. 代码质量问题
2. 设计模式优化机会
3. 代码重复问题
4. 可维护性问题
```

### 深度审查
```
请对 {文件路径} 进行深度代码审查，重点关注：
1. 架构设计是否合理
2. 是否可以使用设计模式优化
3. 性能瓶颈分析
4. 安全性问题
5. 可测试性评估
```

### 重构建议
```
分析 {方法名} 方法，提出重构建议：
1. 当前问题
2. 推荐的重构方案
3. 重构后的代码结构
4. 预期收益
```

## 🎯 专项审查

### 设计模式审查
```
检查代码中是否存在以下问题：
1. 深层嵌套的 if-else → 建议使用策略模式
2. 对象创建复杂 → 建议使用建造者模式
3. 状态转换复杂 → 建议使用状态模式
4. 流程步骤固定 → 建议使用模板方法模式
```

### 性能审查
```
审查代码性能，检查：
1. 是否有不必要的循环嵌套
2. 是否有重复的数据库查询
3. 是否有内存泄漏风险
4. 集合操作是否高效
```

### 安全性审查
```
审查代码安全性，检查：
1. SQL 注入风险
2. XSS 攻击风险
3. 敏感信息泄露
4. 权限校验是否完善
```

## 🔧 常见问题及解决方案

### 问题：深层 if-else
**审查 Prompt:**
```
检查代码中是否存在深层嵌套的 if-else，如果存在，建议使用策略模式重构
```

**解决方案:**
- 使用 Factory + Handler 模式
- 参考: [Factory + Handler 模式](../patterns/factory-handler-pattern.md)

### 问题：代码重复
**审查 Prompt:**
```
检查 {方法A} 和 {方法B} 是否存在重复代码，如果存在，提取公共方法
```

**解决方案:**
- 提取公共方法
- 使用模板方法模式
- 创建工具类

### 问题：方法过长
**审查 Prompt:**
```
检查方法长度，如果超过 50 行，建议拆分
```

**解决方案:**
- 提取私有方法
- 使用策略模式
- 拆分职责

## 🎓 学习要点

每次代码审查后，记录：
1. **发现的问题类型**：如"深层 if-else"、"代码重复"
2. **采用的解决方案**：如"策略模式"、"提取方法"
3. **学到的模式**：如"Factory+Handler"、"模板方法"
4. **最佳实践**：如"Spring List 注入优于 Map"

将这些要点存入知识库，形成审查经验库。
