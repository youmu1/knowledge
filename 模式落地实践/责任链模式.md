# Pipeline + Stage 模式落地实践

## 模式概述

**Pipeline + Stage** 模式是责任链模式（Chain of Responsibility）和模板方法模式的结合体，用于将复杂的业务流程拆解为多个可插拔的阶段（Stage），每个阶段负责特定的处理逻辑。

## 核心组件

### 1. Context（上下文）
承载整个流程中流转的数据对象。

```java
public class OrderProcessContext {
    private Order order;
    private User user;
    private PaymentInfo paymentInfo;
    private Map<String, Object> attributes = new HashMap<>();
    private List<String> errors = new ArrayList<>();
    
    // getters and setters
}
```

### 2. Stage / Processor（处理阶段）
定义单个处理阶段的接口。

```java
public interface ProcessStage<T extends ProcessContext> {
    /**
     * 执行当前阶段
     */
    void execute(T context);
    
    /**
     * 阶段名称，用于日志和监控
     */
    String getName();
    
    /**
     * 是否支持该上下文
     */
    default boolean supports(T context) {
        return true;
    }
}
```

### 3. Pipeline / Chain（管道/链）
负责按顺序驱动各个 Stage 的执行。

```java
@Component
@RequiredArgsConstructor
public class OrderProcessPipeline {
    
    private final List<ProcessStage<OrderProcessContext>> stages;
    
    public ProcessResult execute(OrderProcessContext context) {
        for (ProcessStage<OrderProcessContext> stage : stages) {
            if (!stage.supports(context)) {
                continue;
            }
            
            try {
                stage.execute(context);
                
                // 检查是否应该中断流程
                if (context.shouldStop()) {
                    return ProcessResult.fail(context.getErrors());
                }
            } catch (Exception e) {
                context.addError(stage.getName() + "执行失败: " + e.getMessage());
                return ProcessResult.fail(context.getErrors());
            }
        }
        
        return ProcessResult.success(context);
    }
}
```

## 解决的问题

1. **超长方法**：将 200+ 行的业务方法拆解为多个独立的 Stage
2. **流程僵化**：不同订单类型可能需要不同的处理流程
3. **可测试性差**：长方法难以进行单元测试
4. **流程复用**：某些 Stage 可以在多个流程中复用

## 使用场景

- 订单处理流程（下单 -> 库存检查 -> 支付 -> 发货）
- 审批流程（提交 -> 初审 -> 复审 -> 终审）
- 数据导入流程（验证 -> 转换 -> 清洗 -> 入库）
- 报表生成流程（数据采集 -> 计算 -> 格式化 -> 导出）

## 完整案例：订单处理流程

### 阶段 1：订单验证

```java
@Component
@Order(1)
public class OrderValidationStage implements ProcessStage<OrderProcessContext> {
    
    @Override
    public String getName() {
        return "订单验证";
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        Order order = context.getOrder();
        
        // 验证订单基本信息
        if (order.getItems().isEmpty()) {
            context.addError("订单商品不能为空");
            context.setShouldStop(true);
            return;
        }
        
        // 验证用户信息
        if (context.getUser() == null) {
            context.addError("用户信息不存在");
            context.setShouldStop(true);
            return;
        }
        
        // 验证商品库存
        for (OrderItem item : order.getItems()) {
            if (!validateStock(item)) {
                context.addError("商品 " + item.getProductId() + " 库存不足");
                context.setShouldStop(true);
                return;
            }
        }
    }
    
    private boolean validateStock(OrderItem item) {
        // 库存验证逻辑
        return true;
    }
}
```

### 阶段 2：价格计算

```java
@Component
@Order(2)
public class PriceCalculationStage implements ProcessStage<OrderProcessContext> {
    
    private final CouponService couponService;
    private final DiscountService discountService;
    
    @Override
    public String getName() {
        return "价格计算";
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        Order order = context.getOrder();
        
        // 计算商品总价
        BigDecimal totalAmount = calculateItemTotal(order);
        context.setAttribute("itemTotal", totalAmount);
        
        // 应用优惠券
        if (order.getCouponId() != null) {
            BigDecimal discount = couponService.calculateDiscount(
                order.getCouponId(), totalAmount);
            context.setAttribute("couponDiscount", discount);
            totalAmount = totalAmount.subtract(discount);
        }
        
        // 应用会员折扣
        BigDecimal memberDiscount = discountService.calculateMemberDiscount(
            context.getUser(), totalAmount);
        context.setAttribute("memberDiscount", memberDiscount);
        totalAmount = totalAmount.subtract(memberDiscount);
        
        order.setTotalAmount(totalAmount);
    }
    
    private BigDecimal calculateItemTotal(Order order) {
        return order.getItems().stream()
            .map(item -> item.getPrice().multiply(BigDecimal.valueOf(item.getQuantity())))
            .reduce(BigDecimal.ZERO, BigDecimal::add);
    }
}
```

### 阶段 3：支付处理

```java
@Component
@Order(3)
public class PaymentProcessingStage implements ProcessStage<OrderProcessContext> {
    
    private final PaymentService paymentService;
    
    @Override
    public String getName() {
        return "支付处理";
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        Order order = context.getOrder();
        PaymentInfo paymentInfo = context.getPaymentInfo();
        
        // 执行支付
        PaymentResult result = paymentService.processPayment(
            order.getTotalAmount(),
            paymentInfo
        );
        
        if (!result.isSuccess()) {
            context.addError("支付失败: " + result.getMessage());
            context.setShouldStop(true);
            return;
        }
        
        order.setPaymentId(result.getPaymentId());
        order.setStatus(OrderStatus.PAID);
        context.setAttribute("paymentId", result.getPaymentId());
    }
}
```

### 阶段 4：库存扣减

```java
@Component
@Order(4)
public class InventoryDeductionStage implements ProcessStage<OrderProcessContext> {
    
    private final InventoryService inventoryService;
    
    @Override
    public String getName() {
        return "库存扣减";
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        Order order = context.getOrder();
        
        for (OrderItem item : order.getItems()) {
            boolean success = inventoryService.deductStock(
                item.getProductId(),
                item.getQuantity()
            );
            
            if (!success) {
                context.addError("商品 " + item.getProductId() + " 库存扣减失败");
                context.setShouldStop(true);
                return;
            }
        }
    }
}
```

### 阶段 5：订单创建

```java
@Component
@Order(5)
public class OrderCreationStage implements ProcessStage<OrderProcessContext> {
    
    private final OrderRepository orderRepository;
    private final EventPublisher eventPublisher;
    
    @Override
    public String getName() {
        return "订单创建";
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        Order order = context.getOrder();
        
        // 保存订单
        orderRepository.save(order);
        context.setAttribute("orderId", order.getId());
        
        // 发布订单创建事件
        eventPublisher.publish(new OrderCreatedEvent(order));
    }
}
```

### 使用 Pipeline

```java
@Service
@RequiredArgsConstructor
public class OrderService {
    
    private final OrderProcessPipeline orderPipeline;
    
    @Transactional
    public OrderResult createOrder(CreateOrderRequest request) {
        // 构建上下文
        OrderProcessContext context = new OrderProcessContext();
        context.setOrder(buildOrder(request));
        context.setUser(getCurrentUser());
        context.setPaymentInfo(request.getPaymentInfo());
        
        // 执行流程
        ProcessResult result = orderPipeline.execute(context);
        
        if (result.isSuccess()) {
            return OrderResult.success((Long) context.getAttribute("orderId"));
        } else {
            return OrderResult.fail(result.getErrors());
        }
    }
}
```

## 工程实践要点

### 1. 使用 @Order 注解控制执行顺序
Spring 的 `@Order` 注解可以控制 Stage 的执行顺序：

```java
@Component
@Order(1)  // 第一个执行
public class ValidationStage implements ProcessStage<...> { }

@Component
@Order(2)  // 第二个执行
public class CalculationStage implements ProcessStage<...> { }
```

### 2. 支持条件执行
通过 `supports()` 方法实现条件执行：

```java
@Component
public class VipDiscountStage implements ProcessStage<OrderProcessContext> {
    
    @Override
    public boolean supports(OrderProcessContext context) {
        // 只有 VIP 用户才执行此阶段
        return context.getUser().isVip();
    }
    
    @Override
    public void execute(OrderProcessContext context) {
        // VIP 专属折扣逻辑
    }
}
```

### 3. 支持流程中断
Context 中提供 `shouldStop()` 方法，支持提前中断流程：

```java
public class OrderProcessContext {
    private boolean shouldStop = false;
    
    public void setShouldStop(boolean shouldStop) {
        this.shouldStop = shouldStop;
    }
    
    public boolean shouldStop() {
        return shouldStop;
    }
}
```

### 4. 支持异步执行
某些 Stage 可以异步执行：

```java
@Component
public class AsyncNotificationStage implements ProcessStage<OrderProcessContext> {
    
    @Async
    @Override
    public void execute(OrderProcessContext context) {
        // 发送通知邮件（异步执行，不影响主流程）
        emailService.sendOrderConfirmation(context.getOrder());
    }
}
```

### 5. 支持事务管理
在 Pipeline 层面管理事务：

```java
@Transactional
public ProcessResult execute(OrderProcessContext context) {
    // 所有 Stage 在同一个事务中执行
    // 任何一个 Stage 失败，整个流程回滚
}
```

## 与其他模式的组合

### Pipeline + Stage + Strategy
不同订单类型使用不同的 Stage 组合：

```java
public interface OrderPipelineStrategy {
    List<ProcessStage<OrderProcessContext>> getStages();
}

@Component
public class NormalOrderPipelineStrategy implements OrderPipelineStrategy {
    @Override
    public List<ProcessStage<OrderProcessContext>> getStages() {
        return Arrays.asList(
            validationStage,
            priceCalculationStage,
            paymentStage,
            orderCreationStage
        );
    }
}

@Component
public class VipOrderPipelineStrategy implements OrderPipelineStrategy {
    @Override
    public List<ProcessStage<OrderProcessContext>> getStages() {
        return Arrays.asList(
            validationStage,
            vipDiscountStage,  // VIP 专属阶段
            priceCalculationStage,
            paymentStage,
            orderCreationStage
        );
    }
}
```

## 注意事项

1. **Stage 应该是无状态的**：避免在 Stage 中存储状态，所有状态都保存在 Context 中
2. **异常处理要统一**：在 Pipeline 层面统一处理异常，避免异常中断流程
3. **日志和监控**：每个 Stage 的执行情况都应该记录日志，便于排查问题
4. **性能考虑**：如果 Stage 很多且执行时间长，考虑使用异步执行或并行执行

## 优势与劣势

### 优势
- ✅ 流程清晰，易于理解和维护
- ✅ 每个 Stage 可以独立测试
- ✅ Stage 可以灵活组合和复用
- ✅ 支持流程的动态调整

### 劣势
- ❌ 增加了代码复杂度
- ❌ 需要额外的 Context 对象
- ❌ 调试时需要在多个 Stage 之间跳转

## 适用场景判断

**适合使用 Pipeline + Stage 的场景：**
- 流程步骤较多（>5个步骤）
- 不同业务场景需要不同的流程组合
- 需要支持流程的动态扩展

**不适合的场景：**
- 简单的 2-3 步流程（过度设计）
- 流程步骤完全固定，不会变化
